def node_loads(G):
    return nx.betweenness_centrality(G, normalized=False)


def run_cascade(G, trigger, alpha, tol=1e-9):
    loads0 = node_loads(G)
    capacity = {v: (1 + alpha) * load for v, load in loads0.items()}
    H = G.copy()
    H.remove_node(trigger)
    while True:
        loads = node_loads(H)
        overloaded = [v for v, load in loads.items() if load > capacity[v] + tol]
        if not overloaded:
            break
        H.remove_nodes_from(overloaded)
    largest = max(nx.connected_components(H), key=len) if len(H) else set()
    return len(largest) / G.number_of_nodes()

The small tolerance tol protects the test load > capacity from rounding errors: with \(\alpha = 0\) an unchanged load must not count as an overload.

Validation

Check your code on cases with a known answer before you trust any plot. The chunk below uses the amlab version; run the same checks on yours.

import networkx as nx
import numpy as np

from amlab.networks_cascades import run_cascade, select_trigger, cascade_curve

# A cycle has equal loads everywhere. Removing one node turns it into a path.
C = nx.cycle_graph(12)
print("cycle, alpha = 10:", run_cascade(C, 0, alpha=10).G_ratio, "expected", 11 / 12)

# The centre of a star carries every shortest path.
S = nx.star_graph(10)
print("star, centre removed:", run_cascade(S, 0, alpha=1).G_ratio, "expected", 1 / 11)

# Very large alpha: only the trigger is lost on a well-connected graph.
G = nx.barabasi_albert_graph(100, 3, seed=1)
r = run_cascade(G, select_trigger(G, "load"), alpha=100)
print("BA, alpha = 100: failed per step", r.failed_per_step)

NoteExercise

Explain the output for the cycle with \(\alpha = 10\). Then predict what happens on the same cycle with \(\alpha = 0\) and check it.

TipSolution

After the removal the cycle becomes a path of 11 nodes. Loads grow near the middle of the path, but with \(\alpha = 10\) no node exceeds its capacity, so \(G = 11/12\). With \(\alpha = 0\) the nodes near the middle of the path carry more shortest paths than before, so they fail and the cascade cuts the path into pieces. Run run_cascade(C, 0, alpha=0) to see the final value.

Interpretation

NoteExercise

Compare Figure 1 with your predictions:

  • For which graph and which trigger does the cascade stay small at small \(\alpha\)?
  • How large must \(\alpha\) be before the highest-load trigger stops causing a large cascade on the BA graph?
  • Motter and Lai found that heterogeneous networks are fragile to load-based attacks (Motter and Lai 2002). Does your plot agree? With a single graph realization of 150 nodes, which features of the curves would you trust and which not?
TipSolution
  • No combination keeps the cascade small at \(\alpha = 0\): every curve starts well below 1. Random triggers recover first: \(G\) is close to 1 from about \(\alpha = 0.25\) on both graphs.
  • On the BA graph the highest-load trigger still destroys a large part of the network at \(\alpha = 0.5\), and \(G\) stays below 0.9 up to \(\alpha = 1\). On the ER graph the same trigger stops causing large cascades near \(\alpha = 0.4\) to \(0.5\).
  • Yes: the gap between random and load-based triggers is much larger and lasts much longer on the BA graph, as Motter and Lai found. Trust this qualitative gap. Do not trust the exact values of \(\alpha\) or the small bumps: one graph of 150 nodes and 5 random trials give noisy curves.

Limitations

  • Load follows shortest paths. Electric power follows Kirchhoff’s laws and spreads over all parallel paths.
  • The model has no time: the redistribution is instantaneous. Schäfer et al. (2018) show that transient dynamics of a few seconds matter for real grid cascades.
  • Every node has the same relative margin \(\alpha\). Real equipment has heterogeneous limits and protection settings.
  • A node fails deterministically as soon as \(L_i > C_i\).
  • A single BA graph with \(N = 150\) gives noisy curves. Average over several graphs before you draw conclusions.
TipOptional extension
  • Average the curves over 10 graph realizations and add error bars.
  • Replace the trigger “highest load” with “highest degree” (select_trigger(G, "degree")). Do the two rankings give the same cascade?
  • Load a real network from data/ (for example the USA flights graph) and repeat the sweep on its largest component. Use nx.betweenness_centrality(G, k=..., seed=...) if the exact computation is too slow.

import matplotlib.pyplot as plt

G_er = nx.convert_node_labels_to_integers(G_er.subgraph(max(nx.connected_components(G_er), key=len)).copy())

alphas = np.linspace(0, 1.0, 9)
fig, ax = plt.subplots(figsize=(6, 4))
for G, name, c in [(G_ba, "BA", "C0"), (G_er, "ER", "C1")]:
    ax.plot(alphas, cascade_curve(G, alphas, "random", n_trials=5, seed=1), "o-", color=c, label=f"{name}, random trigger")
    ax.plot(alphas, cascade_curve(G, alphas, "load"), "s--", color=c, label=f"{name}, highest-load trigger")
ax.set_xlabel(r"tolerance $\alpha$")
ax.set_ylabel("G")
ax.set_ylim(0, 1.05)
ax.legend()
plt.tight_layout()
plt.show()
